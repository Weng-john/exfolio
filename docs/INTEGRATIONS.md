# 券商與交易所的資料來源

| 機構 | 方式 | 狀態 |
|---|---|---|
| 任何券商、銀行、交易所 | 上傳對帳單 CSV 或截圖，逐步確認後建立交易 | 支援（Accounts & Positions → 交易 → 匯入券商對帳單） |
| 已是 Exfolio 欄位格式的交易檔 | 標準 CSV 匯入與匯出 | 支援（同一頁的「匯入 CSV」） |
| Binance | 唯讀 API：餘額、合約部位、成交 | 支援（僅本機 Node 後端） |
| 台灣券商（如凱基、永豐） | 唯讀 API | 不支援，請用對帳單 CSV |

目前程式只串接 Binance 的唯讀 API，尚未串接台灣券商：請改用對帳單匯入。

## 對帳單匯入

「匯入券商對帳單」接受兩種來源，兩者都只在瀏覽器內處理，不會上傳：

- **CSV／TSV 匯出檔**：自動偵測編碼（UTF-8、Big5、UTF-16）、分隔符號與標題列，略過表頭說明與合計列。
- **截圖**（PNG、JPEG、WebP 等）：在瀏覽器內辨識繁體中文與英文。第一次使用會從公開 CDN 下載辨識引擎與語言資料（約 20 MB）；圖片本身不會離開裝置。

流程共五步，最後一步確認前不會寫入任何資料：

1. 選擇檔案、帳戶與資金桶。截圖會顯示辨識出的表格，可對照原圖直接修正。
2. 欄位對應：依標題自動建議，沒把握的欄位會標示；可設定日期格式、民國年、股或張、是否估算缺少的手續費，並可存成設定檔供下次同樣格式的檔案自動套用。
3. 逐列檢查：每列的狀態（可匯入、重複、錯誤、需要確認商品）；找不到的商品會提出草稿，由你確認或修改後才建立。
4. 影響預覽：各商品部位變化、各帳戶現金變化、產生的已實現損益與警示（例如賣超、現金變負）。
5. 確認匯入。

每筆交易的 id 由列內容算出，重複匯入同一份檔案或重疊的日期區間不會產生重複交易。

對帳單通常只有成交、沒有入金，匯入後現金會變負。可以選擇補一筆「開帳入金」；這是假設，會影響累積投入與資金加權報酬，取得真實入金紀錄後應替換掉。

### 截圖辨識的限制

- 辨識會出錯：實測中整列結構正確，但個別中文字與標題會看錯，數字也可能混淆（0 與 O、1 與 l、小數點與千分位）。匯入前務必逐格對照原圖。
- 只測過字跡清楚、淺色底、欄位對齊的表格截圖；深色主題、傾斜的照片、多層表頭或被截斷的欄位尚未驗證。
- 一張圖就是一個表格；多頁對帳單需逐張匯入。

## Binance 唯讀同步

### 啟用

後端必須有一把用來加密金鑰的主金鑰，否則這個功能是關閉的，不會保存任何 API 金鑰。

```bash
# 產生一次，放在不進版本庫的地方（例如 .env，已被 git 忽略）
export EXFOLIO_SECRET_KEY="$(openssl rand -base64 48)"
npm run dev
```

主金鑰遺失或變更後，已保存的 API 金鑰無法解開，需要刪除連線重新新增。

### 建立 API 金鑰

在 Binance 的 API 管理頁建立金鑰，**只勾選「啟用讀取」**。建議同時限制可用的 IP。

新增連線時，後端會向交易所查詢這把金鑰的權限。只要開啟了交易、提領、劃轉、槓桿、合約或選擇權任一項，就會拒絕，而且不會保存。之後每次同步都會重新檢查：事後被加開權限的金鑰會停止使用。

### 可以做什麼

- **核對**：把交易所回報的餘額與合約部位，和帳本中對應帳戶的現金、現貨與合約部位逐項比對，列出差異。系統不會自動修改帳本。
- **匯入成交**：依交易對讀取成交並轉成交易。每筆保留交易所的成交編號，重複匯入不會產生重複交易。

### 限制

- 只在本機 Node 後端提供；GAS 後端沒有這個功能。
- 尚未以真實的 Binance 帳戶測試過，只用模擬的交易所回應驗證邏輯。
- 一次最多讀取 1000 筆成交，且需逐一指定交易對。
- 資金費用、入金、出金、理財與空投不會匯入，需手動記錄；核對表會顯示因此產生的差異。
- 手續費以第三種幣別（例如 BNB）支付時不會計入交易，會列出提醒。
- 合約的已實現損益由帳本以先進先出重新計算，可能與交易所的均價法略有差異。

### 金鑰如何保管

- API Key 與 Secret 以 AES-256-GCM 加密後存在 `data/secrets/<會員>.json`，主金鑰只存在後端的環境變數。
- 金鑰不會回傳給瀏覽器（只顯示末四碼），不會寫入日誌，也不在備份檔裡。
- 每位會員只能使用與刪除自己的連線；刪除會員時其金鑰一併刪除。
- 後端只呼叫讀取用的端點，程式中沒有任何下單、提領或劃轉的呼叫。
- 能登入後端主機並同時取得主金鑰與資料檔的人，仍可解開金鑰。這也是金鑰必須是唯讀的原因。
