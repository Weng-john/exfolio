# 部署自己的後端（單人使用的檢查清單）

目的：讓公開網站能用 Google 登入，把資料存在**你自己 Google 帳號**的試算表裡，在手機、平板、筆電、桌機都看得到。完整說明與原理在 [gas/README.md](../gas/README.md)；這份只列一個人自己用時要做的事。

這份清單只有步驟與佔位符。你的 Gmail、試算表網址、部署網址、用戶端 ID 都**不要**寫進這個版本庫、issue 或 PR：它們只該出現在 Google 與 GitHub 的設定畫面裡。

> 後端程式只在模擬環境測過，還沒在真實的 Google 環境跑過。第一次部署請把最後的驗證做完；遇到錯誤，把錯誤訊息（遮掉網址與信箱）交給開發者修。

## 開始前

- [ ] 用來部署的 Google 帳號已開啟兩步驟驗證。之後你的投資資料安全就等於這個帳號的安全。
- [ ] 知道公開網站的來源（origin）：`https://<你的 GitHub 帳號>.github.io`，不含後面的路徑。
- [ ] 讀過 `gas/README.md` 的「安全性：你應該知道的限制」與「已知的弱點」。

## 一、建立 Google 登入用的用戶端 ID

1. [ ] 開啟 Google Cloud Console，建立一個專案（名稱自訂）。
2. [ ] 「API 和服務 → OAuth 同意畫面」：使用者類型選「外部」，發布狀態維持「測試中」，把你自己的 Gmail 加進測試使用者。
3. [ ] 「憑證 → 建立憑證 → OAuth 用戶端 ID」，類型選「網頁應用程式」。
4. [ ] 「已授權的 JavaScript 來源」填公開網站的來源。不需要填重新導向 URI。
5. [ ] 複製產生的用戶端 ID，先放在剪貼簿或密碼管理器，下一段要用。

## 二、建立試算表與指令碼

1. [ ] 在 Google 雲端硬碟建立一份新的試算表。分享設定維持「限制存取」。
2. [ ] 在試算表選「擴充功能 → Apps Script」。
3. [ ] 把編輯器裡的程式換成版本庫的 `gas/Code.gs`。
4. [ ] 「專案設定」勾選顯示 `appsscript.json`，把內容換成版本庫的 `gas/appsscript.json`。
5. [ ] 「專案設定 → 指令碼屬性」新增：

   | 屬性 | 值 |
   |---|---|
   | `ADMIN_EMAILS` | 你的 Gmail |
   | `GOOGLE_CLIENT_ID` | 上一段的用戶端 ID |
   | `MAX_MEMBERS` | `1`（只有你自己用） |
   | `MAX_PENDING` | `1` |

   不要設定 `PASSWORD_LOGIN`：維持只接受 Google 登入。
6. [ ] 在編輯器上方選函式 `setupSheets`，按「執行」並完成授權。試算表會多出 `_users`、`_sessions`、`_config`、`_audit` 四個工作表。
7. [ ] 「部署 → 新增部署作業 → 網頁應用程式」：執行身分「我」，存取權「所有人」。複製部署後的網址。

存取權必須是「所有人」，網站才呼叫得到；保護靠的是 Google 登入與審核，不是網址保密。

## 三、把網址交給網站

1. [ ] GitHub 版本庫 → Settings → Secrets and variables → Actions → **Variables** → 新增 `EXFOLIO_GAS_URL`，值是上一段的部署網址。
2. [ ] Actions → 「Publish public edition」→ Run workflow，等它完成。

網址放在 repository variable，不會進版本庫；但它會出現在建置出的網站程式裡，任何人都看得到，這是預期的。

## 四、第一次登入與驗證

1. [ ] 開啟公開網站，右上角出現「會員登入」，登入頁有 Google 按鈕。
2. [ ] 用 `ADMIN_EMAILS` 的帳號登入。你應該是管理員；`_users` 多一列，`_audit` 有一筆 `register`。
3. [ ] 輸入一筆測試資料並儲存。雲端硬碟會多一份 `Exfolio data …` 試算表；重新整理網頁後資料還在。
4. [ ] 在另一台裝置登入同一個帳號，看得到同一份資料。
5. [ ] 用另一個 Google 帳號嘗試登入：應該被拒絕或停在「待核准」，而且看不到你的資料。確認後在「會員管理」刪除那筆申請。
6. [ ] 開啟 `_users` 與 `_sessions`，確認這兩份工作表所在的試算表沒有分享給任何人。

任何一步不如預期，就先不要輸入真實資料。

## 之後要留意的

- **改了 `gas/Code.gs`**：到「部署 → 管理部署作業」編輯並選「新版本」，網址才會用到新程式。
- **同來源的弱點**：你的 GitHub 帳號底下所有 Pages 網站共用同一個來源。其中任何一個被植入惡意程式，都可能攔截這個網站的登入狀態。要根除得把網站放到自訂網域（OAuth 的已授權來源也要跟著改），或確保帳號底下沒有其他不受你控制的 Pages 網站。
- **沒有流量限制**：陌生人可以耗用每日配額，讓你暫時無法登入或儲存；資料不會因此外洩。
- **備份**：設定頁可以匯出 JSON 備份。備份檔是未加密的，放雲端前請自行加密，也不要放進版本庫。
- **不要分享**：部署網址貼到公開場合雖然不會直接洩漏資料，但會引來不必要的呼叫；試算表則絕對不要開放連結分享。
